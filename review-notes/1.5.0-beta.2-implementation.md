## 3. Screenshot comparison

Every capture was compared pixel by pixel with a small tool built for this run
(`imgdiff`, in the scratch folder), which reports the differing pixel count, the largest channel
difference and the bounding box, and writes a highlight image for anything that differs.

**Method.** The baseline was captured twice from the same build first, to learn what varies on its
own. 13 captures differ between two identical runs: the three screen grabs
(`batch-menu`, `tooltip-view`, `tooltip-filter`, which photograph the screen so a popup renders),
anything with live values (`system-*`, the storage figures on `settings-bottom` and
`settings-diagnostics`) and anything with a relative time ("3 hours ago" on `library-all`,
`library-category`, `library-populated`, `sidebar-expanded`, `library-expanded`). Those 13 are the
noise floor; everything else is stable to the pixel.

**UX-09 (a, b, c, d).** After each of the four commits: **75 of 88 captures pixel-identical, and
the 13 that differed were exactly the noise set** — no capture of the pages that moved differed at
all. The `--screenshot-focus` Tab-order logs for Library, Settings and About matched the baseline
line for line, and every behaviour test (`--test-context-menus`, `--test-library-filter`,
`--test-hover-zoom`, `--test-poster-zoom`, `--test-view-modes`, the three navigation tests,
`--test-automation-names`, `--test-dialog-keys`) produced the same output.

**UX-13.** 57 of 88 identical. The 31 that differ are the 13 noise captures plus 18 that show the
fix: every Settings capture, `nav-settings`, and the ten `focus-settings` frames. On those, the
difference is confined to the tab row and is the anti-aliasing of the tab labels, which now render
inside a `ScrollViewer`; the strip, the pills, the search box and the rest of the page land on the
same pixels. I checked the row's pixel columns directly: at the row's mid-line the two images are
identical apart from that text anti-aliasing, with no shift in position.

**One environmental difference to ignore.** Partway through the session the Windows title bar's
three caption buttons began rendering slightly differently (a 12-pixel run at each button). It is
not the app: a fresh capture from the *original baseline build* reproduces it against the stored
baseline. It shows up as a small difference at the top right of any full-window capture.

## 4. Defaults and judgement calls

1. **How each page is hosted.** The roadmap's brief says the views should inherit the window's
   DataContext. `SystemView` and `ToolsView` are given their own (`{Binding SystemVM}`,
   `{Binding Tools}`), and the Settings markup already scoped itself to `SettingsVM` with an inner
   `Grid`. Following "do it the way System and Tools do it", `SettingsView` is hosted with
   `DataContext="{Binding SettingsVM}"`; `LibraryView` and `AboutView` bind against the
   `MainViewModel` and so inherit it, exactly as their markup did before the move.

2. **What the window still owns.** Drag-and-drop anywhere on the window, the global key handling
   (Ctrl+F, Esc, Ctrl+A, Delete), the click-away that clears a selection, and the launch/import
   toast. The window no longer reaches into any page's named children. It asks the library page
   two questions — `IsFilterFlyoutOpen` and `FocusSearchBox()` — and the pages expose
   `PageSearchBox` for Ctrl+F and Escape, the property `SystemView` already had.

3. **The library drop zone.** Its highlight handlers moved with the page, but the drop itself is
   still the window's: the page calls `HandleDropFromPage` / `HandleDragOverFromPage`, so the
   deferred dispatch and the double-handling guard stay in one place and behave as before.

4. **Resource placement.** A resource moved with the single view that uses it: the three list row
   templates to Settings, both card context menus, both zoom storyboards and the card container
   style to Library. Nothing needed to go to `App.xaml`, because no resource was used by two
   views. `Window.Resources` is now empty and has been removed.

5. **The harness.** `--screenshot-*` and `--test-*` reach the two filter elements through
   `_mainWindow.LibraryPage`, and the four moved resources through `LibraryPage.FindResource`, the
   same way they already reached `_mainWindow.ToolsPage.ToolsList`. Updated in the same commit as
   the move, so no commit in between is broken.

6. **UX-09d, how the size is driven.** Card size and the poster's clip geometry are `sys:Double`
   and `RectangleGeometry` resources (`PosterCardWidth`, `PosterCardClipExtraLarge`, …), swapped by
   one `DataTrigger` on `SettingsVM.IsExtraLargeView`. The two poster views are now a single
   `ItemsControl` that is visible for either mode, so only one set of cards is built instead of two.
   Compact Icons and the Details List are untouched.

7. **UX-13, the three fixes.** Each is the smallest change that holds:
   - **Details list title.** The cell was a horizontal `StackPanel`, which measures its children at
     their full width, so a long title was cut mid-word and the tag beside it sliced in half. It is
     a `DockPanel` now — which docks left by default, so the layout is unchanged — and the title
     trims with an ellipsis in the space that is actually left. At a narrow width a badge can be
     pushed out; the title staying readable is the better trade.
   - **Settings tab row.** Six tabs are wider than a 720 px window and pushed the card search box
     off the row. The row is a `DockPanel` with the box docked first, so it keeps its width, and the
     strip scrolls behind the same edge chevrons the library's category tabs got in `UX-14f`. The
     page subtitle now trims instead of being cut mid-word.
   - **System status card.** The "Performance Optimization Status" heading and the score under it
     ran beneath the three buttons docked beside them, for the same `StackPanel` reason. Docked and
     trimmed, they stop where the buttons start.

8. **A regression I introduced and fixed inside UX-13.** Docking the Settings search box first put
   it ahead of the tabs in the Tab order. `KeyboardNavigation.TabIndex` alone did not fix it,
   because a container whose `TabNavigation` is `Continue` flattens its children into the parent's
   scope; making the strip a `Local` tab group with `TabIndex=0` did. The `--screenshot-focus`
   Settings log now matches the baseline line for line. The fix is amended into the UX-13 commit.

9. **Indentation.** Moved markup was re-indented to the new file's depth and otherwise left
   character for character, so `git diff` of a move is a clean cut and paste.

10. **What I did not change.** Page navigation is still `Visibility`-based (`R-05`), so scroll
    position, per-tab search text and expander state survive switching pages. The library header and
    toolbar rows were moved unchanged and not restyled.

## 5. Out of scope, noticed and not fixed

1. **The library header subtitle clips at 720 px** ("…Xbox, Battle.net, and loca"). The header and
   toolbar rows are off limits by owner decision (`R-01`), so this is reported, not fixed. The same
   one-word fix used on Settings (`TextTrimming="CharacterEllipsis"`) would cover it if you want it.
2. **`--test-library-tabs` fails against a real library.** It clears the games list, adds three
   fixtures and expects exactly four category tabs; with your settings it sees five and throws, and
   because the throw reaches the dispatcher the process stays up until the runner's timeout. It
   fails the same way on the baseline build; it is the test that is data-dependent, not the app.
3. **`--test-automation-names` reports a different System control count run to run** (39 or 82,
   depending on whether hardware detection finished before the audit). Baseline behaviour.
4. **`--test-poster-zoom` occasionally reports a "non-uniform zoom"** when it samples ScaleX and
   ScaleY a frame apart mid-animation (1.043 vs 1.042). It passed on every re-run, baseline
   included.
5. **`LibraryView.xaml` is still 2,017 lines.** The four view modes could each become their own
   control later; this item did not ask for it.
6. **The Details list columns are fixed pixel widths.** At 720 px the title gets about 140 px, which
   is why it needs the ellipsis at all. Making those columns proportional would change the layout at
   normal widths, so it is a separate decision.

## 6. Manual test checklist (highest risk first)

Everything below is what I could not exercise from code: real drag-and-drop, the real keyboard and
pointer, and the tray. Build and run the Debug app, or install a build after backing up
`%AppData%\TrayTrigger`.

**Drag-and-drop (the window keeps this; the pages moved around it)**

1. Drag a game's `.exe` onto the Library's empty-library panel. **Expected:** the import starts once,
   not twice, and the panel highlights blue while the file is over it.
2. Drag the same `.exe` onto the Library while games are already listed (drop over a card, and over
   the space beside the cards). **Expected:** imported once.
3. Drag a `.lnk` shortcut onto the Library. **Expected:** same as a `.exe`.
4. Drag a folder containing several games onto the Library. **Expected:** the folder import dialog
   opens once, and closing it leaves nothing half-imported.
5. Repeat 1 and 4 with Settings, System, About and Tools on screen. **Expected:** Settings, System
   and About accept the drop as the Library does; Tools takes it as a tool, as before.

**Library keyboard (the window's keys, the page's search box)**

6. On Library, press Ctrl+F. **Expected:** the caret lands in the search box with any text selected.
7. Type a word, then press Esc. **Expected:** the search clears.
8. Press Ctrl+A with no text box focused. **Expected:** every visible card is selected; press Esc
   and the selection clears.
9. Click a card, then press Enter, then Ctrl+Enter. **Expected:** Enter opens Game Details,
   Ctrl+Enter launches. Do this in Poster Grid, Extra Large, Compact Icons and Details List.
10. In Details List, select a row with the arrow keys and press Enter, then Ctrl+Enter.
    **Expected:** the same two actions.
11. Tab through Library in each of the four views. **Expected:** every stop shows the blue ring, and
    the arrow keys move between cards by row and column.

**Card menus and multi-select**

12. Right-click one card. **Expected:** the single-game menu, and the card stays lit while it is open.

14. With two selected, press More on the selection bar. **Expected:** the same batch menu opens above
    the bar; Favorite, Change Category and Hide act on exactly those two.
15. Right-click a card that is *not* in the selection. **Expected:** the selection drops and the
    single-game menu opens for that card.
16. Click empty space beside the cards. **Expected:** the selection clears.

**Filter flyout**

    focus is inside it.

    option rather than the vanished Clear button.

    Esc clears it.
26. On Settings, click each tab in turn, including the tab you are already on. **Expected:** the list

27. On Settings, press Tab from the page header. **Expected:** the tabs come first, then the search

**Settings tab row at a small size (UX-13)**
