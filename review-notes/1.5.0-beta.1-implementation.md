## 2. Defaults and judgement calls

1. **UX-01, what stays compact.** These kept their size or went to 9 px:
   - status and platform badges;
   - category pills (the Details list, the poster card chip);
   - About's key caps (10.5 px);
   - the filter-count bubble.

   Icon-font glyphs are not text, so they kept their sizes. Every other text element under 11 px was raised to 11 px.

   #8A8A96 is the owner's chosen value. It reaches 4.97:1 on cards, 4.91:1 on dialogs and 5.49:1 on the window background. It falls short of 4.5:1 only on transient surfaces: 4.44:1 on hover (#252530) and 3.85:1 on active (#2F2F3E). I left it as decided.

2. **UX-02, missing tooltips.** The view buttons, the OPT-IN, RESTART and ADMIN badges, and End Session and Force Close had no tooltips at all. I added short tooltips, worded from the Help topics, so the acceptance could be checked.

3. **UX-03, when Esc asks.** The discard prompt fires on Esc only. Clicking Cancel still discards at once, as before. The Esc handler listens on the bubbling `KeyDown`, so:
   - the hotkey recorder (while recording) and an open combo box consume Esc first;
   - the test table shows Esc and Enter while recording both leave the dialog open.

   Two cases I left alone:
   - **ModernDialog prompts** get no access keys, because their button texts vary per prompt.
   - **Scan for Games and Add Folder** keep their bound "Add N" button label, so no access key there either. Following the roadmap, Enter in these dialogs' filter box now presses the default Add button.

4. **UX-04, ring mechanism.** I used `FocusVisualStyle` (keyboard only) rather than `IsKeyboardFocused` triggers, because the roadmap says "no mouse-only focus rings" and a trigger also fires after a mouse click.

   The hover-only Play overlay on poster cards is now not focusable. Tab onto it used to hide it and drop focus back on the card, a trap present in baseline too. Ctrl+Enter on a focused card still launches.

   Bare `ItemsControl`s (tab strips, card grids, tweak lists) are no longer tab stops.

5. **UX-05, where row names go.** A `Border` has no automation peer, so the composed tweak-row name is on the row's name text and on its buttons, not on the row container.

6. **UX-06, bar placement (the one deviation).** The roadmap says the bar should "overlay or replace the toolbar row". That row is off limits under your instructions, so the bar floats over the bottom of the grid, stacked with the undo toast. The grid never moves either way.

   When the bar appears:
   - **Library:** from one selected game.
   - **Tools:** from two, because a single click selects one tool.

   What else I kept: the existing status-bar hint ("2 selected - right-click one…"), since Help documents it. I added no new view-model logic.

7. **UX-07, summary scope.** The per-game profile summary lists the tier's enabled toggles, as specified. It does not filter by per-game applicability. For example, "GPU preference" is listed for a Steam-launched game even though the tweak does not apply to Steam launches.

8. **UX-10, profile bullet.** I rewrote the third bullet because the roadmap's version was factually wrong (see section 3).

9. **UX-11, Settings undo.** Settings removals are saved at once, as before. Undo re-inserts the entry at its old position and saves again. Only the most recent removal can be undone; this matches the Library.

10. **UX-12, what keeps moving.** The System page spinner and the launch popup's progress sweep keep animating. They are progress indicators, and Windows keeps its own moving with this setting off.

11. **UX-14b, minimum size.** The roadmap says "like Scan for Games", but Scan has no minimum size. I gave the two pickers their opening size as the minimum, so the footer buttons can't be squeezed off.

12. **UX-14e, existing users.** `SessionsStarted` is a new setting, so existing users see the status-bar hint for five more sessions.

13. **UX-14f, Tools strip too.** I applied the fade-and-chevron strip to the Tools tab strip as well, for consistency. The Library tabs, add buttons, search, sort, filter and view controls themselves are unchanged.

14. **UX-15, tab labels.** The roadmap names the tabs "Identity" and "Scripts" but also says tab names must match card headings. I used "Identity & Library" for the tab, and renamed the scripts card heading to "Scripts".

    Skipped as instructed: opening Edit Game on a specific tab ("optional, ask the owner first").

    Edit Tool has two cards, so per the roadmap it gets no tabs.

15. **UX-16, design choices.**
    - A ContextMenu wraps any child that isn't a `MenuItem` or `Separator` in a `MenuItem` container. So the box sits in a `TraySearchRow` container that ignores Enter, Space and clicks.
    - Results are capped at 10 games, then 5 tools.
    - The navigation rows (Games Library, Scan, Settings, Exit) stay visible while a query is active.
    - A separator sits under the search row.
    - Letters typed while a menu row has focus go into the box.
    - A menu rebuild that arrives while the menu is open is deferred until it closes.
    - I built no window or flyout fallback.

16. **Line endings.** My edit tooling rewrote many working-copy files with LF line endings. The repo stores LF and `core.autocrlf=true`, so the commits contain content changes only. `git checkout -- .` or a fresh clone restores CRLF in the working copy if you want it.

17. **Tooling slip (fixed).** A test-file rename briefly overwrote the existing `TrayTrigger.Tests/HardwareDisplayTests.cs`. I caught it when the test count dropped, restored the file before committing, and put my tests in their own file. Nothing of it reached a commit.

## 3. Where the roadmap was wrong or incomplete

- **UX-02:** None of the example tooltips existed: view buttons, OPT-IN, RESTART, ADMIN, End Session and Force Close.
- **UX-04:** "Buttons, combo boxes and checkboxes have their own IsKeyboardFocused triggers" is true for checkboxes, text boxes, filter toggles, help links and cards. It is false for the Accent, Outline, Ghost and Danger buttons, segmented tabs, sidebar buttons and combo boxes. Those fell back to WPF's black dotted rectangle, which is invisible on the dark surfaces.
- **UX-04, missed defect:** A keyboard trap on poster cards (since 1.3.7). Tab or an arrow key from a focused card went to its hover-only Play button, which hid itself and returned focus to the card. As a result, arrow-key spatial navigation could not be observed at all. It works now: Right, Right, Down, Left and Up move between cards by row and column.
- **UX-05:** The cause was bigger than "icon-only buttons". WPF's button automation peer returns an empty name for any button whose content is a panel (glyph plus text), so "Add Game", "Scan for Games", every category tab and every launcher integration checkbox had no accessible name.
- **UX-06:** "Nothing on screen says a selection exists" is only true for a single selected game. From two, the status bar already said "N selected - right-click one for batch actions".
- **UX-10:** "optional per-game performance profiles, off until you choose one" is false. `ImportCoordinator.FinalizeNewEntryAsync` gives every newly added game the **Optimized** profile.
- **UX-12:** The roadmap says "about 35 storyboards". There are two keyed zoom storyboards, used by two poster templates, plus one spinner and the launch popup's code-behind animations.
- **UX-14b:** Scan for Games has no minimum size, so "a minimum size, like Scan for Games" had nothing to copy.
- **UX-15:** The tab list ("Identity", "Scripts") contradicts "tab names must match the card headings".
- **UX-16:** "Host the box as a direct item of the ContextMenu … not inside a MenuItem" is not possible: WPF always wraps it in a MenuItem container. The fix is a container that never activates.
- **Help text:** `Help/tweaks/overview.md` said the restore point is made "before a tweak is applied". It is made before a preset or a restore only. I fixed it with UX-07.
- **For UX-13 (not done here):** At 720 px, the Details list's title column is squeezed to about 70 px ("Cyberpun…"). This is the same in baseline.

### Incident: blue screen during testing (CRITICAL_PROCESS_DIED, 0xEF)

**What happened.** At about 14:52 the PC stopped with bug check 0xEF. The minidump is `C:\WINDOWS\Minidump\091926-9562-01.dmp`. The last log line was the Close Game test starting its fake game a second time, just before the test's Force Close step.

**Cause (almost certain; the dump was not analysed, no debugger installed):**

1. The first version of `--test-close-game` used `C:\Windows\System32\charmap.exe` as the fake game, so the game's install folder was System32.
2. When Force Close has no usable handle to the game, it falls back to killing every process under the install folder. That fallback is already in 1.4.5.
3. The Claude session was elevated, so the test's TrayTrigger was too, and could kill critical processes such as `csrss.exe`.
4. The first test run had already force-closed an unrelated System32 process (PID 28648). The stub-handoff logic had taken it for the "real game" after Character Map closed within 0.4 s. That run didn't crash.

**Fix (`fe8583d`).** `ProcessPathResolver.FindProcessesUnderDirectory` is the only place processes are found by folder. It now refuses:

- the Windows folder and anything under it;
- drive roots;
- the top of Program Files (both), Common Files, ProgramData, Users, the user profile and both AppData folders.

It also skips:

- TrayTrigger's own process;
- processes in other sessions;
- any process Windows marks critical (`IsProcessCritical`), or that can't be asked.

17 new tests cover this, including that nothing is found under System32.

**Also fixed in `1cd005a`:**

- Close Game and Force Close mark the exit as final, so a quick exit is never taken for a launcher stub.
- Both act on their own `Process` objects. The session's object is disposed by its exit handler, which could happen in the middle of `Kill`. That left a spurious "No process is associated with this object" and a needless fallback folder scan.

**Test changes.** `--test-close-game` now runs a copy of Character Map from `%TEMP%\TrayTrigger-close-game-test` and first checks that System32 is refused. All 8 checks pass: System32 refused, the game starts, Close Game closes it, its process exits, the session ends, it starts again, Force Close kills it and ends the session, and closing with nothing tracked reports that. `settings.json` and `games.json` were unchanged throughout.

**Recommendation.** Ship `fe8583d` in the next release, even on its own. Any user whose game resolves to a system folder, running TrayTrigger as administrator, could hit the same crash from Force Close in 1.4.5.
